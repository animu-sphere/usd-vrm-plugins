# CI routing audit and baseline, 2026-10-31

Observed at `de7317a` before routing changes. This report is dated evidence;
[BUILDING.md](../../guides/BUILDING.md#ci) owns the current CI contract.

## Generation boundary

The checksum-verified Windows release of OST **0.23.13**, the version pinned in
`openstrata.ci.yaml`, regenerated the committed source workflow byte-for-byte
after newline normalization. The workstation's default OST was 0.23.14 and was
not used to establish that result. Inspection of OST's `ost-ci` matrix schema
and GitHub renderer found no path-routing, required-gate or `workflow_call`
contract; unknown matrix fields are rejected.

The repository adapter invokes the pinned generator, changes only the workflow
trigger and PR job event guards, and checks its expected input shape. The seven
cells, runtime digests, provenance/SBOM verification, Windows Python 3.13,
Windows L4 cap, Linux X11 packages, cache keys and every build/test/package step
are unchanged. `generate.py --check` compares the complete adapted result.

Actionlint 1.7.12 accepts the hand-authored routing/called workflows. Both the
original raw OST output and the adapted source workflow report the same existing
expression diagnostic: the workspace test command references `matrix.up_to`,
which is absent from that workspace matrix. The adapter does not change that
OST-generated command. All other actionlint diagnostics were checked without
suppressions; this existing diagnostic is not a clean lint result.

Upstream reports filed on 2026-10-31 after checking for existing issues:

- [OpenStrata #275](https://github.com/animu-sphere/open-strata/issues/275):
  undefined `matrix.up_to` in a test-only workspace workflow. Reproduced in raw
  output from both 0.23.13 and the latest published release, 0.23.14; the issue
  includes a single-cell manifest and actionlint reproduction. The pyramid
  step is normally skipped for `verify: test`, so no hosted runtime failure is
  attributed to this lint defect.
- [OpenStrata #276](https://github.com/animu-sphere/open-strata/issues/276):
  opt-in native reusable source-workflow generation for downstream docs-only
  routing, including PR/manual caller guards and deterministic regeneration.
  Path classification and required-result aggregation can remain downstream.

## Cache evidence and limits

For that latest source run, workspace Linux missed its key while the
[bundle Linux job](https://github.com/animu-sphere/usd-vrm-plugins/actions/runs/41164583789/job/124429299741)
restored its key and logged successful verification followed by skipping the
remote pull. Both use runtime digest `sha256:3bf31789...`, but their keys differ
by cell name. This demonstrates partitioning and one missed sharing opportunity;
it does not prove whole-registry cache contents are interchangeable or establish
a hit-rate distribution. Shared keys, cache reservation races and post-change
P50/P95 remain follow-up experiments. No cache semantics or verification gates
were changed. OST remains owner of the generated cache implementation.

## Routing verification and rollout

The stdlib-only routing tests cover code/config/unknown paths, Markdown inputs
used by release/consumer tooling, empty diffs, 3,500-path diffs, a late code path,
Unicode/newline filenames, invalid SHAs, git deletion/rename, fork-style diverged
base/head histories and synchronize commits. Gate tests reject every failure,
cancellation, missing dependency/output and unexpected skip on both routes.
The adapter is tested for preserved steps and refusal of unfamiliar shapes.

The required gate covers changes, docs, generation drift, all seven OST cells
through their reusable workflow, plain CMake, and installed-package consumption
including its cross-platform comparison. Docs-only selects no OST bootstrap,
runtime pull, CMake, CTest or package job. Manual dispatch selects every lane.
No pull_request_target or secrets were introduced.

Read-only branch-protection inspection returned `Branch not protected`; the
effective rules endpoint returned no rules for main. No remote settings were
modified. A protected deployment should require `ci-required` and remove legacy
conditional cell names before adopting this routing.

Local verification covers Python tests, documentation/release-note checks,
pinned regeneration/drift detection, and workflow lint with the existing OST
diagnostic above. Hosted PR/fork execution, check presentation, actual post-change
duration and cache correctness still require GitHub Actions runs. Rollback is
to revert the routing/adapter change, restoring each original PR trigger; the
matrix and test inventory are unchanged.
