## Authentication Notes

- Anonymous push is denied by GHCR.
- `ost artifact push` works with `OST_REGISTRY_USER` and `OST_REGISTRY_PASSWORD`.
- `write:packages` is enough to push.
- Deleting a GHCR package version requires `read:packages` and `delete:packages`.
- Temporary token files were removed after publication and tag cleanup:

```text
$HOME/private/tmp/token.txt
$HOME/dev/usd-vrm-plugins/token.txt
$HOME/dev/usd-vrm-plugins/ost-ghcr-token.txt
$HOME/private/tmp/ost-ghcr-token.txt
```

## Findings

1. `ost runtime export --slim` produces a compact runtime artifact suitable for
   per-PR CI pulls; the macOS SDK artifact was about 33 MB compressed.
2. `ost artifact push` is sufficient for publishing to GHCR once a token is supplied.
3. Digest-pinned references remain the stable CI primitive; human-readable tags are
   useful for package browsing and manual pulls.
4. GHCR tag cleanup is clumsy because tags are grouped under package versions, and
   `ost` has no first-class retag/untag command.

## Requests to OpenStrata v0.12.0

1. Add or document `ost artifact tag` / `ost artifact untag` workflows for OCI
   registries, especially GHCR.
2. Document required GHCR token scopes:
   `write:packages` for push, plus `read:packages` and `delete:packages` for cleanup.
3. Consider an `ost artifact push --tag-only` or `--retag` mode that can attach a tag
   to an existing OCI digest without re-uploading or forcing package-version deletion.
4. Keep CI configuration digest-pinned, but recommend a stable tag convention for
   runtime packages, such as:

```text
<openusd-version>-<platform>
26.05-macos-arm64
26.05-linux-x86_64
26.05-windows-x86_64
```
