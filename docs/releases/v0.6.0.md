# v0.6.0 — VMC input

**Release status:** tagged `v0.6.0` on 2026-08-03.

## Objective

Make the first product-specific input leaf reach the existing live-capture
path without creating a second motion pipeline. VMC Protocol arrives as
OSC-over-UDP datagrams and becomes canonical humanoid motion; retargeting,
stage authoring, and evaluation remain in their existing layers.

## What ships

- **`vrmAdapterVmc`**, a plain static library. It decodes OSC packets and VMC
  messages, maps Unity `HumanBodyBones` names and coordinates to
  `motion::HumanBone`, assembles complete frames, and bridges them to
  `motion::LiveCaptureSource`.
- **`vmc-packet-capture` v1 and a generated corpus.** Captures retain the raw
  datagrams and their arrival order before any decoder can refuse them. Corpus
  tests replay those bytes through each layer; the UDP loopback test also proves
  that a real socket produces the same poses as replaying the file.
- **`vmc_record`**, a CLI that records a bounded live session or inspects an
  existing capture. It reports receive, decode, frame, and intake statistics in
  one place, and identifies the condition that stopped a recording.
- **Exact and tolerant motion comparisons.** `motionCore` now provides exact
  equality for registered value types and `NearlyEqual` for parity and corpus
  checks, with a single tolerance derived from the recorded-trace precision.

## Compatibility

- **OpenUSD:** exactly 26.08 on Windows x86_64, macOS arm64, and Linux x86_64.
- **Schema contract:** version 1, unchanged.
- **Package version:** all workspace manifests and the aggregate product use
  `0.6.0`.
- **No authored VRM or VRMA stage contract changes.** The adapter is an input
  leaf over `motionCore` and `motionRuntime`; it introduces no plugin bundle or
  OpenUSD registration.

## Known limitations

- The committed VMC corpus is generated and proves protocol shapes, not behavior
  from a particular sender. Validating sender applications, a relay, and a real
  capture device remains operator work.
- The adapter reports hips-offset and root movement but does not decide how a
  sender intends those positions to compose.
- OpenExec evaluation, realtime skinned display, and other input adapters are
  not part of this release.
