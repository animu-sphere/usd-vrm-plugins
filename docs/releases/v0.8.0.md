# v0.8.0 — installed-package consumer lane, shared OSC foundation and VRChat OSC Trackers input

**Release status:** prepared 2026-08-31.

## Objective

Two halves, one boundary, one tag.

**Distribution.** Every package this workspace installs is shown to configure,
resolve and link from a **clean prefix**, driven by a consumer project that
names no target from this source tree. Five phases of splitting checked every
boundary they created *from inside*, and a composed build resolves every target
in-tree and never opens a package config file — so a package could name an
unresolvable target with every lane green. On 2026-08-29 two of them did. The
general fix is not another in-tree check; it is a consumer that is not us.

**Input.** One live session reaches the **unchanged** canonical motion and
retarget pipeline through a **third** independently modelled surface — VRChat
OSC tracking input — over a protocol-neutral OSC decoder and a shared transport
layer that no adapter keeps a private copy of.

They ship together because they are the same boundary seen from two sides: a
third adapter *and* the proof that what this workspace produces can be consumed
from outside it. Tagging a release whose own packages are unverified is the
thing the first half exists to stop.

**A tracker source is not a pose source.** VMC and mocopi transport humanoid
bone transforms; VRChat OSC carries numbered tracker observations, which are
pre-IK, and a tracker index is not a body role. So the adapter stops at a
`TrackerFrame`, and the humanoid solve is a separate, generic boundary — this
track pushes no VRChat-shaped type into `motionCore` under any outcome.

## What ships

### Distribution — a consumer that is not us

- **[PACKAGE_CONTRACT.md](../architecture/PACKAGE_CONTRACT.md)**, the binding
  distribution contract, derived from the CMake sources rather than written
  beside them. Per package: the `find_package` name, the exported target, the
  header root, the packages that must resolve first, the platform libraries that
  travel on the link line, aggregate membership, and whether standalone
  installability has been **measured** or only reviewed. Twelve packages take a
  contract; three plugin bundles export no target and install no config **by
  design**, and the document says so rather than leaving them absent. It answers
  "what do I write to consume this", which WORKSPACE.md §5 was repeatedly asked
  and never stated.
- **Three scripts, each runnable by hand**, because a lane nobody can reproduce
  is a lane nobody can debug: `check_package_consumer.py` (one package, into a
  scratch prefix holding nothing else, with the fixture copied **outside** this
  repository so it cannot resolve through the tree it came from),
  `run_package_consumer_lane.py` (every contract row on one host — the set is
  *read* through the driver's parser, never listed, so a thirteenth package
  cannot enter the contract without entering the lane), and
  `check_package_closures.py` (criterion 6, which no single host can answer).
- **A PR-gating lane on all three OS**
  ([`package-consumer.yml`](../../.github/workflows/package-consumer.yml)):
  read the pins, consume on each platform, compare the three closures. It
  **copies no pin** — `scripts/ci_pins.py` reads runners, digests, host packages
  and the Python version out of `openstrata.ci.yaml` through `ost ci matrix`,
  and the three OS come from the three `verify: test` workspace cells.
  `release.yml`, the other hand-authored workflow here, copies all three and is
  how a tag build failed while every PR lane stayed green.
- **`scripts/check_docs.py` refuses a `*Config.cmake.in` with no contract row**,
  and a row naming a package that does not exist.

### The foundation the third adapter forced

- **`libs/liveTransport`**, the live half's shared leaf: the UDP receiver, the
  bounded queue, the packet-capture format and the diagnostic vehicle, once
  instead of once per adapter. 1485 lines left `vrmAdapterVmc` and 337 arrived;
  1781 left `vrmAdapterMocopi` and 359 arrived, and every committed capture in
  both corpora still round-trips byte for byte.
- **`libs/osc`**, the OSC wire format once: packets, bundles and their
  flattening, addresses, type tags, arguments, and a refusal naming the byte and
  the address it refused at. It knows no address *semantics* — `/VMC/…`,
  `/tracking/…` and `/avatar/…` are all just addresses here.
- **Both extractions waited for a second consumer.** The decoder moved on
  measured evidence rather than belief: an address inventory written in
  `vrmAdapterVrchatOsc`, decoding real bytes through the VMC-owned decoder
  without moving it, needed **five VMC tokens** — every one of them the name,
  exactly the three couplings the plan predicted and nothing else.
- **No adapter imports a sibling adapter**, verified by injection in every
  direction rather than by the green result. With a third adapter the trio is
  symmetric.

### VRChat OSC tracking input

- **`vrmAdapterVrchatOsc`** and **`vrchat_osc_record`**, with a frozen ten-code
  diagnostic set. The extraction's receipt is the file sizes: a capture format
  that was ~400 lines written twice is one magic string and four forwarding
  calls here, and the receiver is a `switch` over two transport events.
- **A real session was inventoried before a decoder was written.** Six captures,
  44 918 datagrams: **eight addresses — three numbered trackers and a named
  `head`**, every one `,fff`, one message per datagram, no bundles, in a fixed
  eight-datagram cycle inside a median 0.053 ms; ~58 Hz emitted, ~39 Hz
  delivered ([report 02](../reports/motion/02-2026-08-30-vrchat-osc-address-inventory.md)).
  The inventory carrying **no list of expected addresses** is what made `head`
  arrive as a row instead of as four absences.
- **The tracking space is measured, not assumed.** The documented space *is* the
  measured one — metres, +Y up, +Z forward, left-handed — so the conversion is
  VRM 1.0's reflection through X. A recorded rest pose settled four of five
  readings; handedness came from a take labelled "head **left**, centre, right",
  where a left turn reports −77.5° of yaw
  ([report 03](../reports/motion/03-2026-08-30-vrchat-osc-tracking-space.md)).
- **Frame assembly is stated policy with a fixture each**, not emergent
  behaviour. The frame boundary is report 02's measurement rather than a
  convention — a burst 0.053 ms wide against a 17 ms interval — and it is **two**
  rules, because a repeat needs no clock and a gap catches a frame no repeat
  would close. A peer that changes is a restart; a silence of any length is a
  timeout and nothing more; a caller with no peer never sees a restart at all.
  `session-restart` and `silent-gap` are the same 4.8452 s gap told apart by
  identity alone — testable only because the capture format grew a per-record
  peer the same day.
- **Twelve generated fixtures**, written from report 02's measurements rather
  than from VRChat's published surface. One is the session's own shape; five are
  marked `derived` and six `unobserved`, each with its reason, because a corpus
  that cannot say how far a recording stands behind each fixture is one a later
  reader has to guess about.
- **`libs/motionTracking`**, which says *which tracker is which body region*
  without saying which bone — the assignment policy, in neither the adapter nor
  `motionCore`.

### The solve boundary, and what this release claims

- **Assigned observations reach a `HumanoidPose`** in `libs/motionTracking`. The
  solve is direct, and a position it does not consume is **reported rather than
  dropped**, because consuming one is IK.
- **A capture reaches a rig through unchanged tools.** `vrchat_osc_record
  --inspect --export-trace --assign` writes the canonical trace, and
  `vrchat_osc_record_endToEnd` drives it through **unchanged** `motion_capture`
  and `motion_retarget`. **The claim is a partition rather than a count**: four
  joints move and fourteen hold their rest pose *exactly* — not within a
  tolerance, because nothing authored them — and four of the fourteen sit
  between a driven hip and a driven foot, which is where a solve that had begun
  estimating would show first.
- **This release therefore claims tracker *input*, not tracker-driven motion.**
  That is the second of the two branches the plan wrote in advance, taken
  deliberately.

### Cross-source evidence

- **Three paths, two performances, and the loss stated rather than papered
  over** ([report 04](../reports/motion/04-2026-08-31-cross-source-carry-drop.md)).
  The one-physical-session comparison v0.7.0 ran is **not producible on this
  sender**: its transfer format is exclusive *and* it records no BVH while
  sending OSC. What replaces it is five labelled sequences performed separately
  on both dates, with the two 2026-08-15 paths kept in as the control — where
  they agree to 0.00° and the third differs, the difference is the third path's.
- **Eight difference categories, and the one the plan predicted would matter
  produced the largest difference in the comparison — and it was a defect.** On
  the take whose answer is known in advance (stand still for twenty seconds) the
  tracker path's head and both feet snapped **33.6°** on 16 of 777 frames while
  the hips did not move: a frame whose hips tracker sent a position and no
  rotation had its children localised against identity. 33.6° is the hips' own
  orientation, to five figures. Fixed in the same change; the worst single-frame
  step goes to **2.46°**, with nothing over 5°. Two tests asserted the defect and
  now assert the opposite — every internal check passed against it, because
  within one frame the composition is exactly self-consistent.
- **Report 01's one row that mattered is closed.** All three paths now carry the
  body's travel, and re-running the identical 2026-08-15 capture through today's
  tool prints that report's sentence with the verb the other way round. What is
  lost is distributed rather than concentrated: the BVH export re-bases the body
  to the origin and loses the room; the tracker path loses eighteen bones and a
  third of the frames its sender emits; no path carries tracking state, because
  neither wire has a field for it.

### Two defects a lane could not have found

- **The VRMA reader was built by every CI lane and tested by almost none of
  them.** `plugins/usdVrmaFileFormat/CMakeLists.txt` guarded its tests on
  `USDVRMA_BUILD_TESTS`, a name nothing outside that file set, so in a composed
  root build the bundle registered **zero** CTest targets — on three platforms,
  on every PR, since the workspace cells landed. A test that is never registered
  is not reported anywhere, which is why a 100%-passing suite hid it.
- **A tool member of the installed product could not find the product's own
  data.** `motion_bvh_convert`'s installed-prefix rule was one directory too
  shallow for the aggregate product, so the whole BVH path was unusable from a
  release artifact — the profiles shipped byte-identically to the directory
  WORKSPACE.md §5 names, and the tool beside them looked somewhere else. It was
  found by *running* it: four sources agree on the destination and one of them
  was wrong about where the reader stands.

## Compatibility

- **OpenUSD:** exactly 26.08 on Windows x86_64, macOS arm64, and Linux x86_64.
- **Schema contract:** version 1, unchanged.
- **Package version:** every workspace descriptor, every declared `requires`
  range (`>=0.8,<0.9`), every CMake standalone fallback and the aggregate
  product read `0.8.0`. Forty-six files, seventy-five lines, bumped together —
  the lockstep v0.7.0 restored after five releases of drift.
- **No authored VRM or VRMA stage contract change.** The tracker path produces a
  `motion-capture-trace` and a `UsdSkelAnimation` through the existing tools; it
  adds no stage vocabulary.
- **The aggregate product has 7 members**: the four bundles and the three
  `tools/` CLIs. Ten member archives are produced — four bundle packages and six
  tool packages — and the three adapter CLIs are subtracted by declaration
  (`openstrata.toml`'s `release_exclude`), leaving exactly `release_members`;
  packaging fails with `AGGREGATE_MEMBERSHIP_MISMATCH` otherwise. In v0.7.0 that
  exclusion was a property of the pinned `ost` version rather than a
  declaration. **Measured on the pinned `ost` and not a workstation's**: the
  pin in `openstrata.ci.yaml` and this host both read **0.22.8**, which is the
  divergence that cost v0.7.0 five wrong documents.
- **`liveTransport` and `osc` are outside the aggregate product's link closure**
  and ship 9 and 7 files respectively. A change in either count is a change in
  what the excluded side ships.
- **Verified at the bumped version, not before it**: the workspace dependency
  graph reports 4 bundles, 1 bundle edge, 12 libraries, 19 library edges, valid
  — so no dependent range was left behind by its provider — and the workspace
  suite is **125 of 125** passing, with all four bundles green through the L0–L5
  pyramid.

## Known limitations

Everything in this section is stated because it was **measured or attempted**,
not because it was foreseen.

### The release conditions this milestone did not close

- **No redistributable VRChat OSC session is committed.** The 2026-08-30 session
  is manifest-only under the corpus policy, for the same reason as the mocopi
  sessions: a session is a real person's motion. The three CTest names that read
  the corpus — `_corpus`, `_trackerCorpus`, `_loopbackCorpus` — would pick a
  redistributable session up with **no change**, so this is open on the bytes
  and not on the code.
- **The VRChat OSC Euler order is measured to three of six.** A head turning
  does not roll, which refuses the three compositions that do not apply the yaw
  outermost, and no sample in the session rotates about two axes at once by
  enough to separate the rest — the second-largest component of any orientation
  across 44 918 messages is 25.2°. The residual is quoted rather than waved at:
  median **0.21°**, **12.33°** at worst, against 25.7° before the test. One
  labelled *rolled* take — twenty seconds of hardware — settles it.
- **The end-to-end leg runs on a fixture rig and a generated capture.** Both
  sibling adapters drive `Seed-san.vrm` beside theirs; this one drives a fixture
  rig, from `rig-motion`, a capture written for this leg — because every other
  capture in the corpus drifts too little to survive a retarget's rest-pose
  correction as a visible rotation. A recorded session reaching a released
  avatar is an operator's twenty minutes.
- **The `unknown` difference row is one entry**: 15.5° on the right-hand head
  turn, which two separate performances cannot distinguish from a sender
  difference.
- **A VMC relay session still does not exist**, so the VMC half of the root/hips
  decision stays open and a VMC session still retargets in place.
- **Tracking loss remains unproducible on the mocopi product**, so
  `VRM_MOCOPI_TRACKING_LOST` stays frozen and unraised.
- **The live path does not run from release artifacts alone.** The recorded path
  does, as of 2026-08-30. `mocopi_record` is not in the aggregate — it left by
  declaration — so that run composes the product with the adapter's own
  artifact, which `ost library package` can now produce and nothing has yet
  performed.

### Packaging and distribution

- **`release.yml` stays hand-authored** and hand-mirrors what the CI contract
  now expresses: its X11 step, its `ost` pin and its runtime digests are copies.
  Regeneration never touches them, and a green PR lane proves nothing about it —
  which is why a `workflow_dispatch --ref` dry run precedes the tag. Adopting
  `ost`'s release contract is the eventual fix and is not scoped.
- **No lane publishes an adapter artifact.** `ost library package
  adapters/liveCapture/mocopi` produces `vrmAdapterMocopi-0.8.0-<target>.tar.zst`
  — the shape WORKSPACE.md §5 has named since before anything could emit it —
  but `release.yml` stages the aggregate's members only. Whether a release
  carries adapter artifacts is an open **decision**, not a missing tool.
- **PKG-2's prefix question is not fully closed.** Every consumer run used a
  `cmake --install` prefix. For a plain library that prefix and an extracted
  `ost` package are the same seven files; `vrmSchema` is the one row where the
  two could still diverge, and `--prefix-source ost-package` against it is
  unrun.
- **A standalone configure of an adapter *with* its CLI is unmeasured.** The
  driver installs each package into a prefix holding exactly its declared
  closure, and an adapter's CLI has edges the adapter is refused — so each
  adapter carries a `<PACKAGE>_BUILD_TOOL` option the driver sets `OFF`. That
  shape is what `ost library build` exercises instead.
- **The three-platform verification cases run against synthetic reports.** The
  Windows halves are real; the macOS and Linux halves are the substitution the
  lane expects. What they establish is that each rule fires on the shape it is
  aimed at — what the shape actually is, only the lane establishes.
- **The Linux and macOS symbol baselines are still unfrozen.**
  `tests/baseline/symbols/` holds `windows-x86_64.txt` only, and `--check` skips
  a platform with no committed file. Every other baseline artifact is verified
  on all three OS.
- **There is no real-runtime compatibility lane.** The scheduled lane and its one
  cell were removed on 2026-08-30: it targeted a self-hosted runner that does not
  exist, so every weekly firing since 2026-07-27 was cancelled after queueing,
  and it paired a 26.05-built plugin with a 26.08 runtime. Reinstating it needs a
  real runner, a republished plugin artifact **and** a re-added cell.
- **`ost` cannot report that a workspace member ran no tests.** The VRMA defect
  above is ours and is closed; what stays open is that nothing would report the
  next one. Asked upstream as per-member attribution in `ost test --json`.
- **Two verbs cannot be spelled in the CI contract.** A `kind: workspace` cell
  takes `verify: graph|build|test`, so `ost plugin test --workspace` and `ost
  plugin package --workspace` — the two verbs `release.yml` runs by hand — have
  no generated construct. Three per-bundle cells remain to reach them.

### Scope deliberately outside this release

- **The humanoid solve stops before IK.** Tracker observations become a
  `HumanoidPose` by direct assignment; estimating an unobserved joint is a solve
  this release does not perform, and a position it cannot consume is reported.
- **Expressions do not reach a rig.** A VRM expression binds N morph targets
  across M meshes plus material colours, so `motion_retarget` authors no
  `blendShapeWeights` and no `skel:blendShapes` binding. That is
  `ExpressionResolve`, in a later release.
- **Look-at is untouched, in every layer.**
- **No Avatar Parameters, OSC eye tracking, OSCQuery discovery, OSC sender or
  router, two-way VRChat client integration, or realtime display.** A VRChat
  client is never a test dependency: every replay test completes with nothing
  installed.
- **OpenExec evaluation of any kind is a later release**, and since 2026-08-29 it
  sits behind the recorded-source and producer-contract tracks as well — a
  compute layer over contracts that are still moving evaluates a boundary twice
  instead of once.
- No FBX reader, no NPZ/AMASS reader yet, and no `SdfFileFormat` bundle for
  `.bvh`.
