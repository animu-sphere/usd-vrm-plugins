# v0.4.0 — offline retarget

**Release status:** tagged `v0.4.0` on 2026-07-26.

## Objective

Make the motion layer produce something a user can watch. v0.3.0 authored an
avatar-independent clip that nothing consumed; v0.4.0 completes the retarget
core and ships the tool that binds a clip to a real rig. This is the motion
layer's **first end-to-end evaluation point** (motion policy §16-C).

## What ships

- **Workspace Phase 6b — `motionRuntime`:** a plain static CMake library over
  `motionCore`. `PoseBuffer` (bounded, strictly ordered history; bracketed
  sampling; capped position-only extrapolation), `SlerpShortest` / `LerpPose` /
  `LerpRootMotion`, `Resample` / `SampleAnimation`, `PoseFilter`
  (frame-rate-independent exponential smoothing), and two- and N-pose
  `BlendPoses`.
- **Workspace Phase 6b — `vrmRetarget`:** the offline retarget core.
  `TargetSkeleton`, `HumanoidMap`, `SourceRestPose` / `RestPoseCorrection`,
  `RootMotionPolicy`, `PoseRetargeter`. No stage, no OpenExec.
- **Motion Phase C — `motion_retarget`:** the bake tool. Reads a target rig and
  a semantic clip off stages, retargets, authors the `UsdSkelAnimation`, and
  binds `skel:animationSource` on an override of the referenced skeleton.
- **The design triplet is executable.** `canonical_walk.usda` + `avatar.usda`
  now reproduce `expected_retargeted.usda` in a test, compared at the value
  level through USD composition on both sides.
- **Retarget semantics are in the contract.**
  [`MOTION_CONTRACT.md`](../design/MOTION_CONTRACT.md) gains a Motion Phase C
  section: explicit binding, the rest-pose correction's world-delta invariant,
  and root motion as a rest-relative delta.

## The defect that made the whole thing visible

Both the importer and the bake authored a `UsdSkelAnimation` without `scales`.
UsdSkel resolves translations, rotations and scales as a unit and `scales`
carries no schema fallback, so the clip bound cleanly, read back every authored
value correctly, and then resolved **every joint to the skeleton's rest pose**.
Opened in usdview, a `.vrma` did not move
([#64](https://github.com/animu-sphere/usd-vrm-plugins/issues/64)).

Both halves now author a constant identity array. Scale is still never animated
— the array exists only so the clip evaluates. The tests that missed it compared
authored attribute values; the tests that replace them drive a
`UsdSkelSkeletonQuery` and compare *resolved* transforms against the animation,
because the query succeeds and returns a full-length array either way.

## Using it

```bash
motion_retarget \
  --avatar avatar.vrm \
  --animation walk.vrma \
  --output character_walk.usda
```

A `.vrm` avatar carries its own humanoid mapping through
`vrm:humanBones:<bone>`. A rig that does not needs an explicit map:

```bash
motion_retarget --avatar rig.usda --animation walk.vrma \
                --output character_walk.usda \
                --humanoid-map humanoid.json
```

where `humanoid.json` is `{"hips": "Root/Pelvis", "spine": "Root/Pelvis/Spine"}`.
`--root-motion hips|root|ignore`, `--root-joint`, `--translation-scale`,
`--preserve-target-height`, and `--resample HZ` control the bake;
`motion_retarget --help` is authoritative.

## Three decisions

- **Joint names are never guessed.** A binding comes from the avatar or from an
  explicit map. An unbound bone the clip drives is reported; a joint the clip
  does not drive keeps its rest transform instead of collapsing to identity.
- **Root motion carries a delta, not a height.** A clip authored on a 1.0 m rig
  drives a 1.6 m one without the avatar snapping to the source's hip height.
- **The retarget core never opens a stage.** `tools/motionRetarget` is the only
  stage-aware component, which is what lets `execVrm` wrap `vrmRetarget` later
  rather than reimplement it, and lets a future live source reuse it with no
  stage at all.

## Compatibility and artifacts

- **OpenUSD:** cy2026 / 26.05; tolerated range `>=25.05,<27.0`.
- **Platforms:** Windows x86_64, macOS arm64, Linux x86_64.
- **Schema contract:** 1, unchanged. v0.4.0 introduces no new typed VRM schema —
  the retargeter reads `vrm:humanBones:*` as plain attributes and links no
  schema bundle.

Per target the release publishes the same four member archives as v0.3.0
(`vrmSchema`, `usdVrmFileFormat`, `usdVrmPackageResolver`,
`usdVrmaFileFormat`, each at `0.4.0`), plus the aggregate product archive,
source archive, and checksums.

## Known limitations

- **`motion_retarget` is not in the published artifacts.** It is an executable,
  not a bundle, and the aggregate product has no member shape for one. Tracked
  as a P1 ask in
  [report 28](../reports/ost/28-2026-07-26-v0.20.0-motion-layer-ci-gap.md); build
  it from source in the meantime.
- **No CI lane compiles or tests the motion layer.** `motionRuntime`,
  `vrmRetarget`, and `motion_retarget` are covered by the plain-CMake root build
  only, because `ost ci generate` emits one job per bundle cell. Same report,
  P0 ask.
- Retargeting is **offline and rotational**. No IK, no foot locking, no contact
  handling, no blending beyond the primitive `BlendPoses`. Scale is authored as
  a constant identity array and never animated.
- Expressions, look-at, live capture, generation, and OpenExec evaluation remain
  Motion Phases D–H.
