# v0.11.0 — native animated USD export and spring bones

**Unpublished.** This candidate has no publication evidence yet. The tag,
hosted closure results, asset inventory and registry digests must be recorded
before this becomes a released-version record.

## Objective

Ship the existing native-export improvements and the VRM secondary-motion
foundation. The candidate is bounded by the
[0.11.0 changelog](../../CHANGELOG.md#0110--2026-10-31);
renderer integration, new expression/look-at computations, ExecIr, VRMA
writing and VRM round-trip are outside its scope.

## What ships

- `vrm_export --motion <clip.vrma>` reuses `motion_retarget` for body,
  expressions and look-at. Native `.usda`, `.usdc` and `.usdz` outputs reopen
  without source files or VRM plugins; `--flatten` composes one layer.
- Native export localizes external and embedded images, reports dependencies
  with `--dependency-report`, diagnoses unresolved assets and produces
  reproducible `.usdz` bytes per architecture across hosts and time zones.
- `vrmRig::SpringBoneSolver` steps VRM 1.0 chains and VRM 0.x root subtrees
  with sphere/capsule colliders, center-space history, explicit reset and
  independent copies. The caller owns scheduling and stage adaptation.
- VRM 0.x collider offsets convert source-local Z to the glTF joint basis.
- Schema contract **2** distinguishes spring roots (`vrm:rootJoints`) from
  ordered chains (`vrm:joints`). Installed-consumer and release-closure checks
  verify the declared product and required gates on each product OS.

## Compatibility and migration

- Package version **0.11.0** is lockstep across the workspace, six bundles,
  two libraries and two tools. Internal ranges are `>=0.11,<0.12`; consumed
  `usd-motion-plugins` artifact pins and ranges stay at their existing values.
  The added solver API and schema interpretation change require a minor bump
  under [the package contract](../architecture/PACKAGE_CONTRACT.md#31-a-requires-range-between-two-releases).
- OpenUSD remains exactly **26.08**, with OpenExec, on Windows x86_64,
  Linux x86_64 and macOS arm64. Separate `vrmImaging` lookdev packages target
  Windows and Linux x86_64; there is no macOS lookdev runtime.
- Reimport VRM 0.x assets where possible. To migrate an existing v1 stage,
  move spring root values to `vrm:rootJoints`, remove the old `vrm:joints`
  opinion and preserve parallel parameters and collider relationships.
  VRM 1.0 ordered chains keep `vrm:joints`. Updating the version marker alone
  is insufficient; see the
  [migration contract](../../plugins/vrmSchema/docs/SCHEMA_CONTRACT.md#migrating-v1-spring-declarations).
  `VRM271` rejects mismatched contracts and `VRM256` rejects ambiguous arrays.

## Accepted limitations

These existing distribution limitations are accepted for this candidate;
they remain follow-up work in the
[package-portability backlog](../roadmap/backlog.md#package-portability).
Passing the current gates is still required; this table exempts no gate.

| Limitation | Release disposition and boundary |
| --- | --- |
| Linux/macOS build-machine RPATHs | Accept the existing carry-over only while installed-artifact smokes pass without loading checkout libraries. Relocatable RPATH cleanup remains B01. |
| OpenUSD registration macros retain source filenames | Accept the existing diagnostic-path disclosure; no source content is distributed by those strings. |
| Multiple bundles can carry copies of one shared library | Accept the composed product's tested loader resolution; independent mixed-version bundle installations are not established. |
| Standalone dependency USD registration is incomplete upstream | Recommend the aggregate product or explicitly composed bundles; do not claim a lone importer package is sufficient. B03 retains the extracted-bundle/CMake-prefix question. |
| No Linux/macOS symbol baseline or second runtime/min-version lane | Accept the exact OpenUSD pin and current three-OS behavior/consumer coverage; B02/B04 remain open. |
| Hand-authored release workflow and last-build library staging | Retain the descriptor-derived build order, product-library check, reproducibility check and closure checklist. Upstream replacement remains conditional. |

The spring solver requires rigid metre transforms and fixed rest translations;
non-unit scale and extended colliders remain outside this API's measured scope.
Native USD export does not export VRM or bake spring simulation. Rendering,
resident spring sessions and fixed-tick hosts belong to their consuming repos.
The existing material/imaging limitations remain in
[supported configurations](../reference/SUPPORTED_CONFIGURATIONS.md).
