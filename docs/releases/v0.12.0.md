# v0.12.0 — pinnable libraries for C++ consumers

**Release status:** [published v0.12.0](https://github.com/animu-sphere/usd-vrm-plugins/releases/tag/v0.12.0) on 2026-10-31,
tag commit `47206d992c9d0124f8098d510912986198fd8e23`.

## Objective

Let another repository build against `vrmRig` and the typed `vrmSchema` API by
digest. `usd-avatar-runtime` v0.2.0 needs this for its native VRM session, and the
[0.12.0 changelog](../../CHANGELOG.md#0120--2026-10-31) bounds the release.

## What ships

- `vrmRig` and the new `vrmSchemaSdk` as GitHub assets and GHCR packages for
  `cy2026` / `usd` on Windows, Linux and macOS, with a pin table.
- Every existing bundle, tool and the product, rebuilt against motion 0.5.4.

## Compatibility and migration

- **Schema contract:** stays at 2. No stage needs to be reimported.
- **Library API:** none is added or changed in this repository.
- **Motion:** every pin moves from 0.5.1 to 0.5.4, within the existing
  `>=0.5,<0.6` range. A consumer that combines these packages with its own motion
  pins should use 0.5.4.
- **Ranges:** internal `requires` ranges move to `>=0.12,<0.13`, so 0.11.0 packages
  no longer satisfy them.
- **Package name:** consume `vrmSchemaSdk` by pin and `find_package(vrmSchema)`. Pin
  it or use the `vrmSchema` bundle in one prefix, not both: they carry the same files.

## Accepted limitations

- The `vrmSchema` bundle package still has no headers, and its CMake target still
  names them. Teaching `ost plugin package` to carry declared headers is a separate
  question for `open-strata`.
- `vrmSchemaSdk` has no `package_contract`, because `ost library verify-consumer`
  cannot resolve OpenUSD from a declared closure. `usd-avatar-runtime` builds against
  the package instead.
- The distribution limits in the [v0.11.0 record](v0.11.0.md) otherwise stand.

## Verification and publication evidence

- The [main-SHA dry run](https://github.com/animu-sphere/usd-vrm-plugins/actions/runs/41209980807) and the [tag workflow](https://github.com/animu-sphere/usd-vrm-plugins/actions/runs/41211519218) passed on all cells at that commit.
- The release holds 73 assets. `external-library-pins.json` lists `vrmRig` and
  `vrmSchemaSdk` for Windows, Linux and macOS, and a registry pull of `vrmRig` for
  Windows passed with fresh, credential-free `ost` state.
- `usd-avatar-runtime` built its VRM session against these pins on Windows: 20/20
  tests, four real-avatar runs, and `hydra-toon`'s resident VRM check. Its
  [capability matrix](https://github.com/animu-sphere/usd-avatar-runtime/blob/main/docs/reference/CAPABILITY_MATRIX.md) records the details.
- The `usd` bundles and the product were not exercised against a consumer beyond the
  release workflow's own closure checks.
